## Fallstricke dieser Runde (teuer bezahlt — je 2–4 Zeilen)

1. **`docker.io` auf Debian 13 (trixie) liefert KEIN docker-Binary** — nur `docker-init`, zieht dafür ~120 MB `dockerd`/`containerd` ins Image. Fix: offizielles statisches Binary `docker-27.3.1.tgz` von `download.docker.com` nach `/usr/local/bin/docker` entpacken, `ca-certificates` für HTTPS-Download.

2. **Image gebaut ≠ Binary drin ≠ Container läuft drauf** — drei getrennt zu belegende Stufen: `docker compose build` (Image), `docker stop+rm+up -d` (Recreate, neuer Container), dann erst live messen. Rebuild bereitet nur vor.

3. **Docker-outside-of-Docker: `-v` braucht den HOST-Pfad.** Container-Pfad `/app/.hermes/sandbox_runs` existiert auf dem Host nicht → Docker legt still ein **leeres** Verzeichnis an → Skriptdatei fehlt (`python: can't open file '/sandbox/<id>.py'`). Auflösung: eigene Container-ID via `HOSTNAME`/`socket.gethostname()`, dann `GET /containers/{id}/json` über `docker_client` (Allowlist `^/containers/[^/]+/json$`), **längster Destination-Präfix-Match** unter den Mounts, Override `ARCHON_SANDBOX_HOST_DIR`, nicht auflösbar → **fail-closed** (Error, kein Docker-Aufruf).

4. **Eine Notbremse verlegt die Tür, sie schließt sie nicht:** `/api/sandbox` auf 501, während das Frontend auf `/api/sandbox/execute` zeigte — und **dieser** Pfad fiel auf Host-Python zurück (`engine:"isolated_subprocess"`). Engine-Strings (`docker_micro_container` vs. `isolated_subprocess`) sind der Beleg, nicht die Doku.

5. **Allowlist-Anker:** `^/containers/json$` matcht `/containers/json?all=true` **nicht** → stiller Fallback auf `load_services()`, `/api/services` liefert keine echten Container mehr. Fix: `^/containers/json(\?.*)?$`.

6. **Route NIE löschen, nur Handler deaktivieren** — sonst fällt die Parität auf 584/860 (SSE-Endpunkt beim MC-Router-Auslagern mitgelöscht, ~8 min Degradierung). Regel: Löschbereich aus Handler-Grenzen ableiten (`awk '/^(async )?def |^@app\\./' main.py`), Decorator-Zahl vorher einfrieren (`grep -cE '@app\\.(get|post|put|patch|delete|websocket|api_route)\\('`).

7. **Fehlende `update_mc`-Injektion ist `RuntimeError`, kein stiller `save_mc`-Fallback.** Zwei Linien im selben Modul — vereinheitlicht: fehlende Injektion → `RuntimeError` (Commit `df1e560a`).

8. **Ein Lock über einem `await` ist tabu.** Deshalb Move-Handler zweiphasig: erst atomar schreiben (`update_mission_control_data`), dann Seiteneffekte (Synthese-Finalisierung, `execute`, `fan_in`) **ohne** Lock.
