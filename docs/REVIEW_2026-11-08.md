### 3.1 Logik

**R-01 🔴 Profil-Löschung ohne Freigabe, wenn bereits ein Gate offen ist**
`archon/services/profiles_service.py:489-500`
Der `else`-Zweig kehrt nur zurück, wenn **kein** pending-Gate existiert. Existiert eins,
fällt die Funktion durch zum `shutil.move(...)` am Ende. Wirkung: zwei DELETE-Aufrufe →
das Profil ist nach dem zweiten Aufruf gelöscht, ganz ohne Owner-Bestätigung; der Agent
verliert Agent-Identität, Rollen und Historie. Die Rückgabe meldet dabei `"status": "success"`.
```bash
sed -n '489,500p' archon/services/profiles_service.py
# if not _pend: ... return {"status":"pending_owner_approval"...}   <- kein return im if-Zweig
grep -n "shutil.move" archon/services/profiles_service.py
```

**R-02 🔴 Crash-Recovery setzt laufende Tasks auf `todo`**
`backend/operations_api.py:51-61` (Writer bei `:411`)
`started_at` wird als ISO-String geschrieben, die Recovery vergleicht aber
`CAST(started_at AS REAL) > 0 AND CAST(started_at AS REAL) < :cutoff_ts`. SQLite castet
`'2026-11-08T09:00:00'` zu `2026.0`; das ist für **jeden** ISO-Wert `> 0` und `< 1.7e9` →
die erste ODER-Klausel ist immer wahr. Wirkung: beim ersten DB-Zugriff je Prozess werden
**alle** laufenden Tasks auf `todo` zurückgesetzt (auch der vor 30 s gestartete). Der Agent
arbeitet weiter und schreibt danach `done` auf einen Task, den das Board als offen zeigt →
Doppel-Dispatch, doppelte LLM-Kosten, widersprüchliche Events.
```bash
sed -n '51,61p' backend/operations_api.py
grep -n "started_at = ?, WHERE id" backend/operations_api.py   # ISO-Writer
python3 -c "print(float('2026.0') < 1.7e9)"                     # True -> Klausel trifft immer
```

`raw_lines = payload.get("lines", [])` — ein Update ohne `lines` (z. B. nur `notes`)

`backend/fleet_self_healing.py:31-43`
`service_name` kommt ungeprüft aus dem URL-Pfad in `f"docker restart {container_target}"`

**N-01 🔴 Shutdown-Drain blockiert die Event-Loop, die er abwarten soll**
`backend/graceful_shutdown_coordinator.py:131-133` (aufgerufen aus `main.py:8571` / `11592`)
